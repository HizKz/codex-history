# Repository guidance

## Project

`codex-history` is a Go TUI that browses, searches, and resumes local Codex
conversations through the Codex app-server protocol. Keep conversation data on
the user's machine and preserve support for macOS and Linux.

## Layout

- `cmd/codex-history`: CLI entry point and subcommands.
- `internal/appserver`: JSON-RPC process lifecycle and Codex thread APIs.
- `internal/history`: protocol-item normalization and searchable transcript text.
- `internal/index`: local SQLite metadata and full-text index.
- `internal/config`: embedded defaults, strict TOML decoding, and key validation.
- `internal/tui`: Bubble Tea state, commands, key handling, and rendering.
- `examples/config.toml`: documented configuration example.
- `package.nix`, `flake.nix`, `.goreleaser.yaml`: distribution definitions.
- `docs/architecture.md`, `docs/releasing.md`: detailed design and release notes.

## Required invariants

- Use `codex app-server`; do not parse private rollout JSONL or Codex SQLite files directly.
- Never commit real conversation text, credentials, usernames, or home-directory paths as fixtures.
- Do not upload or log conversation content. Search data must remain local.
- Keep command output, MCP arguments/results, and expandable tool details out of the search body.
- Reserve `ctrl+c` as an unconditional emergency exit.
- Keep the Go build CGO-free and cross-compilable to supported Linux and macOS targets.
- Keep terminal rendering safe for narrow terminals and full-width Unicode text.
- Do not tag, publish a release, update a tap, or submit a package without explicit user authorization.

## Change rules

- For app-server changes, verify method and field names against a schema generated by the installed Codex CLI. Update fake-server tests without copying real history.
- For configuration changes, update the Go struct, embedded `default.toml`, `examples/config.toml`, validation, and tests together.
- For key changes, check conflicts in every active scope and preserve the emergency binding.
- For index changes, preserve file permissions, literal-query behavior, schema migration safety, and the privacy boundary above.
- Keep blocking I/O out of Bubble Tea `Update`; perform it in `tea.Cmd` functions.
- Preserve existing CLI flags and config semantics unless the requested change explicitly introduces a breaking change.

## Verification

Run the smallest relevant checks while iterating. Before handing off a code
change, run:

```sh
gofmt -w cmd internal
go mod tidy -diff
go test ./...
go vet ./...
```

For concurrency, protocol, TUI, index, packaging, or release changes, also run
the applicable checks:

```sh
go test -race ./...
staticcheck ./...
env GOOS=linux GOARCH=amd64 CGO_ENABLED=0 go build -o /tmp/codex-history-linux-amd64 ./cmd/codex-history
nix build --no-link 'path:.#codex-history'
nix develop 'path:.' -c goreleaser check
```

Use `go run ./cmd/codex-history doctor --json --no-cache` only when a live local
Codex compatibility check is useful. Do not include conversation bodies in its
output or in reports.

## Completion

A change is complete when behavior is covered by tests, public documentation
and examples match it, privacy and compatibility invariants still hold, and the
working-tree diff contains only intended files.
